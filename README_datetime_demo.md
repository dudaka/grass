# GRASS DateTime Wrapper Demo

This directory contains demo programs to test the Python wrapper for GRASS datetime functionality generated by ctypesgen.

## Files

1. **`simple_datetime_demo.py`** - A minimal demo showing basic datetime functions
2. **`test_grass_datetime_demo.py`** - A comprehensive demo testing all major features
3. **`run_datetime_demo.bat`** - Windows batch script to run both demos easily

## Generated Wrapper

The demos test the Python wrapper generated from:
- `C:/opt/grass/build/output/lib/grass85/include/grass/datetime.h`
- `C:/opt/grass/build/output/lib/grass85/include/grass/defs/datetime.h`

The wrapper is located at:
- `C:/opt/grass/build/output/lib/grass85/etc/python/grass/lib/date.py`

## Troubleshooting

### Import Errors
If you get import errors like `Import "grass.lib.date" could not be resolved`:
1. Check that the GRASS library was built successfully
2. Verify the generated `date.py` file exists
3. Make sure the library path in the script matches your installation

### Library Loading Errors
If you get errors loading the `grass_datetime` library:
1. Check that `grass_datetime.dll` (or `.so` on Linux) exists in the library directory
2. Verify the `--compile-libdir` path is correct
3. Make sure all dependencies are available

### Function Call Errors
If individual function calls fail:
1. Check the function signatures in the generated wrapper
2. Verify the ctypes argument types match the C function parameters
3. Look for GRASS error messages using the error handling functions

## Using the Wrapper in Your Code

After verifying the demos work, you can use the wrapper in your applications:

```python
import sys
sys.path.insert(0, r"C:\opt\grass\build\output\lib\grass85\etc\python")

from grass.lib.date import (
    DateTime,
    datetime_is_leap_year,
    datetime_days_in_month,
    DATETIME_ABSOLUTE
)

# Check if a year is a leap year
is_leap = datetime_is_leap_year(2024, 1)
print(f"2024 is {'a leap' if is_leap else 'not a leap'} year")

# Get days in a month
days = datetime_days_in_month(2024, 2, 1)  # February 2024
print(f"February 2024 has {days} days")

# Create and use DateTime structures
dt = DateTime()
dt.year = 2025
dt.month = 9
dt.day = 4
dt.mode = DATETIME_ABSOLUTE
```

## How --compile-libdir Helped

The `--compile-libdir "C:\opt\grass\build\output\lib\grass85\lib"` option in your ctypesgen command:

1. **Told ctypesgen where to find libraries**: During wrapper generation, ctypesgen needed to locate the `grass_datetime` library (specified with `-lgrass_datetime`)

2. **Added to library search path**: The path was added to the compile-time library search path so ctypesgen could successfully load and analyze the library

3. **Embedded in wrapper**: The path is stored in the generated wrapper as `_libdirs = ['C:\\opt\\grass\\build\\output\\lib\\grass85\\lib']`, which helps the wrapper find the library at runtime

4. **Essential for Windows**: On Windows, libraries are not typically in standard system paths, so explicitly specifying the location with `--compile-libdir` is crucial for successful wrapper generation

Without `--compile-libdir`, ctypesgen would not have been able to find the `grass_datetime` library during processing, resulting in a wrapper that couldn't properly interface with the GRASS datetime functions.
